## OBJECTIVE

Превратить amberrajewelry.com из «хорошего масс-маркет jewellery-сайта» в **high-jewelry house experience**: при первом визите возникает ощущение «это дорого и сделано брендом уровня Cartier», при этом путь к покупке удобен и быстр.

**User stories:**
- Новый VIP-визитёр заходит → hero вызывает «вау», бренд воспринимается как люкс, а не artisan-этно.
- Покупатель листает каталог → фильтрует по цвету янтаря/металлу/цене, видит сортировку, попадает на PDP.
- На PDP → зумит макро, видит 360°/макро-галерею, выбирает размер, читает про сертификат, добавляет в корзину.
- Checkout → понятная оплата/доставка ИЛИ явный made-to-order flow.

## SUCCESS CRITERIA (конкретные, измеримые)

- [ ] **Hero**: full-bleed кинематографичный кадр (видео loop ИЛИ статика студийного макро изделия), h1 ≥ 64px display, LCP < 1.5s на 4G, CLS 0. Мнение Владимира «теперь дорого».
- [ ] **Каталог**: фильтры (категория + цвет янтаря + металл + ценовой диапазон) + сортировка (популярные/цена/новые) + masonry-сетка. 0 regressions по существующим 94 товарам.
- [ ] **PDP**: отдельная страница товара с зум-галереей (≥4 ракурсов), размерным гидом, блоком сертификата/происхождения, related-изделиями.
- [ ] **Checkout**: задокументированный путь (полный checkout ИЛИ made-to-order flow) — без тупиков.
- [ ] **Perf**: Lighthouse mobile Performance ≥ 90, LCP < 2.0s, CLS < 0.05 — на index, shop, PDP.
- [ ] **A11y**: Lighthouse a11y = 100 (уже было, не уронить).
- [ ] **Список съёмки**: документ со спецификацией кадров/видео под каждую секцию — готов к продакшну.

## BOUNDARIES

- **Always**: мерить перф до/после изменений; не ломать существующие переводы (15 языков); деплойить только через `vercel --prod`; бэкап CSS перед правкой; cache-bust версий при смене ассета.
- **Ask first**: новые зависимости/JS-фреймворки; смена CSS-карты страниц; удаление секций; изменения в Airtable-схеме; запуск платной AI-генерации.
- **Never**: откатывать прогресс (правило проекта); коммитить `.env`/секреты; править `amberra.css` для index/shop (и наоборот); использовать `mix-blend-mode:multiply` / `mask-image` на model.png (артефакты).

## OPEN QUESTIONS

1. **Checkout**: сейчас есть реальная оплата (Stripe/BOG/иной) или только request-a-piece? Определяет P4.
2. **3D-капля**: оставляем как signature-элемент в hero (вписанной в сцену) ИЛИ меняем на продукт-видео/фото?
3. **PDP**: отдельная HTML-страница на товар (`/products/<slug>`) или расширенный drawer? Текущее — drawer.
4. **Фото изделий**: качество текущих `images/<cat>/` — достаточно для макро/зума, или все 94 надо переснять?
